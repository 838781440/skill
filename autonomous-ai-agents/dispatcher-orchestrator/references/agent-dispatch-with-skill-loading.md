# 带 Skill 加载的 Agent 派发模式

> 本模式在 2026-06-07 "结婚成本"快速分析中验证通过。用户反馈"好了" = 模式正确。

## 标准 context 模板

派发 agent 时，context 必须包含三个要素：

1. **使用的 skill 名称** 及其核心要求
2. **具体任务**
3. **强制输出格式**（匹配 skill 规范）

### 模板

```python
delegate_task(
    context=f"""
你正在使用 **finance-financial-analyst** skill 作为方法论框架。

该 skill 的要求：
1. 先陈述假设，再给出结论
2. 必须构建场景分析（基准、乐观、悲观）
3. 区分事实与预测
4. 对每项建议做敏感性测试

你的任务：分析中国结婚成本。
需要搜 3-5 条关键数据（标注来源和证据等级 🔵🟡🟠🔴）

输出格式（必须遵守）：
【发现】数据之间的矛盾和冲突，不是数据本身
【财务模型/推演】成本收益分析、场景推演（至少3层）
【关键假设】核心假设是什么，不成立会怎样
【敏感性分析】假设变动10%结论是否翻转
【证据等级】🔵/🟡/🟠/🔴
""",
    goal="分析结婚成本现象",
    toolsets=["web", "search"]
)
```

## 成功案例

### 结婚成本 · 3路专家（2026-06-07，用户认可）

| 专家 | 使用的 Skill | 输出核心 | 用户反馈 |

### 失败案例（供反思）

| 模式 | 问题 | 用户反馈 |
|:----|:----|:--------|
| 不加载 skill，只给角色名 | 无框架，输出浅 | "内容有点干" |
| 不加载 skill，只写"用prism方法" | 太抽象，agent 不知道怎么用 | "专家你真的有用skill里面的专家吗" |

## skill 加载 vs 不加载的输出质量对比

| 对比项 | 不加载 skill | 加载 skill |
|:------|:----------|:---------|
| 分析框架 | agent 自己发挥，质量看运气 | 有标准方法论（财务/心理/人类学） |
| 输出格式 | 不一致，随缘 | 统一的【发现】【因果链】【证据等级】 |
| 深度 | 数据表+浅层结论 | 矛盾发现+3层因果推演+隐藏假设 |
| 用户评价 | "我自己上网查有什么区别" | "好了" |
