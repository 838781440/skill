# 深度分析标准范式

> 以下模式在"年轻人躺平"深度分析中验证通过（6个专家，~20分钟完成）。

## 1. 专家配置参考（社会议题）

| 专家 | 分析角度 | 核心问题 |
|:----|:--------|:--------|
| 社会学 | 现象定义、舆论传播、代际差异 | 这个现象的本质是什么？被媒体放大了吗？ |
| 经济学 | 就业、收入、房价、代际财富 | 经济驱动力是什么？成本收益如何？ |
| 比较制度 | 跨国对照、制度差异、政策效果 | 其他国家同样情况怎么发展的？可以抄吗？ |
| 心理文化 | 心理动因、社交媒体、价值观变迁 | 表面行为和真实心理一样吗？ |

> 技术/商业类议题换对应的 engineering/marketing 专家即可。

## 2. 每个专家的输出格式

```
### 分析点N：[标题]

**【发现】**
数据之间的矛盾和冲突。不是"XX数据是多少"，而是"XX数据和YY数据放在一起，暴露了什么"。
例：青年失业率17.8%但起薪没跌→说明中间层岗位在消失，不是工作少了

**【因果链】**
至少3层推演，用箭头串联：
A → B → C → D → E
例：房价高→推迟结婚→推迟生育→育龄妇女减少→出生人口连降

**【隐藏假设】**
这个领域的分析默认了什么前提？这个前提可靠吗？
例："躺平是主动选择"→但低学历躺平可能是被排除在就业市场外的被迫状态

**【证据等级】**
🔵可查证 / 🟡行业共识 / 🟠估算推演 / 🔴经验判断
```

## 3. 交叉对质格式

```
### ⚠️ 交叉对质

| 分歧点 | 对比 |
|:------|:----|
| X | 专家A说A / 专家B说B → 为什么分歧？谁更可信？ |

共识点：所有专家都同意的2-3个判断
盲点：所有人都没注意到的1-2个角度
```

## 4. 整合洞察

所有视角合并后，只能从交叉中看到的**唯一洞察**。

好的整合洞察标准：
- 不是"综上所述"式的废话
- 不是任何一个专家单独能说出来的
- 读完之后让用户觉得"原来是这样"

## 5. 实操经验

### 5.1 致命错误（踩过的坑）

| 错误 | 表现 | 用户反馈 |
|:----|:----|:--------|
| 专家当搜索员用 | 只返回数据点+结论的表格 | "内容有点干，我自己上网查有什么区别" |
| 调度师当汇总器用 | 把专家结论直接罗列 | 缺乏深度，用户感觉不值 |
| 输出用HTML标签 | `<details>`在微信不渲染 | 显示异常 |

### 5.2 正确做法

- **数据采集占20%，分析占80%**。每个专家先搜3-5条锚点数据，然后大部分时间花在推演上
- **专家要有立场**。不同专家应该得出不同的结论，完全一致的结论说明角度没有切分开
- **调度师负责找矛盾**。如果所有专家结论一致，调度师的工作就是找他们共同的盲点
- **必须先加载skill再派。** skill_view('finance-financial-analyst') → 把 skill 的方法论要求和输出格式写进 context。参考 `references/agent-dispatch-with-skill-loading.md`。

## 6. 触发示例

```
用户说："深度分析 年轻人躺平"
→ 调度师匹配：社会学+经济+制度比较+心理文化 4个专家
→ 每人限10-15次工具调用
→ 输出：报告摘要→专家洞察→交叉对质→核心结论
```
