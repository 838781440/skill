# Grill Me（方案拷问）

对方案、计划或设计进行系统性拷问，一次一个问题，走完所有决策分支，直到方案没有明显漏洞。

**本质：** 这不是动手验证（那是 pressure-test 干的事），这是帮你**把脑子里的假设挖出来晒一晒**。

---

## 触发方式

| 你说 | 触发模式 |
|:----|:--------|
| **grill me** | 标准模式：走完全部分支 |
| **快速拷打我** | 紧凑模式：问 3-4 个关键问题就收，5分钟内完成 |
| **grill me about [主题]** | 针对某个方案/计划拷问 |
| **拷打我 / 找漏洞** | 同上 |
| **stress test my plan** | 同上 |

---

## 工作流程

### Phase 0: 了解背景

先问 1-2 个问题搞清你在说什么。**快速模式只问 1 个。**

```
clarify(question="你要拷问的是什么？一个产品方案？技术设计？还是创业想法？")
```

如果用户提供了文档/代码，先读一下再问。**快速模式跳过这一步，直接问。**

### Phase 1: 逐分支拷问

一次只问一个问题，走完所有分支：

**快速模式：** 只问 3-4 个最关键的问题就收。判断标准——第一个问题就涵盖了方案的"目标+用户+落地"三要素，后续问题根据回答动态裁剪。用户表现出不耐烦（"好了吗"、"还要多久"）时立即跳到收尾总结。**宁少勿拖，用户耐心有限。**

**标准模式：** 走完至少 6-8 个关键维度。

**通用拷问维度清单（不需要全问，根据方案类型选）：**

| 维度 | 拷问方向 | 适用场景 |
|:----|:--------|:--------|
| 🎯 **目标** | 你要解决什么问题？怎么知道做对了？ | 全部 |
| 👥 **用户** | 谁在用？他们真的在乎吗？ | 产品类 |
| 💰 **成本** | 要花多少时间/钱？值不值？ | 全部 |
| ⚔️ **竞争** | 别人为什么没做？或者做了你凭什么赢？ | 创业/产品 |
| 🔧 **技术** | 最可能崩在哪里？降级方案是什么？ | 技术方案 |
| 📈 **规模** | 10 个用户和 1 万个用户一样吗？ | 技术/产品 |
| 🔒 **风险** | 最坏情况是什么？你怎么兜底？ | 全部 |
| 🚀 **落地** | 第一步做什么？谁来做？多久？ | 全部 |

**结果不存 gbrain，对话即用即弃。** 拷问是临时对需求，不污染知识库。

**提问方式：**

```
clariy(
  question="你说目标用户是独立奶茶店店主，你确认过他们真的愿意为小程序付费吗？",
  choices=[
    "聊过几家，有意向",
    "还没聊过，猜测有需求", 
    "他们愿意用免费版但不一定付费",
    "这个还没想清楚"
  ]
)
```

规则：
- **一次只问一个问题。** 等用户回答再问下一个。
- 问题要尖锐但不对抗。目的是帮用户发现盲区，不是嘲讽。
- 提供 2-4 个合理的选择项（不是泛泛的"是/否"）。
- 如果用户能通过读代码/文档自己找到答案，先去读，不要问。
- 基于用户的回答，决定走哪个分支继续追问。

### Phase 2: 收尾总结

当所有关键分支都走完后，输出总结：

```
## 拷问总结

### 已确认的决策
- [决策 1]
- [决策 2]

### 未解决的问题
- ❓ [问题 1] — 建议下一步：[行动]
- ❓ [问题 2] — 建议下一步：[行动]

### 风险预警
- ⚠️ [风险 1] — 如果不解决可能：[后果]
- ⚠️ [风险 2] — 如果不解决可能：[后果]

### 建议的下一步
1. [行动项 1]
2. [行动项 2]
```

## 与其他工具的配合

这套分析工具包（prism + pressure-test + grill-me）由 dispatcher-orchestrator 统一调度，详见 `autonomous-ai-agents/analysis-toolkit-pipeline.md`。

**三个工具的关系：**
```
🧠 prism（深度分析 → 弄清结构）
   ↓
🔧 pressure-test（压力测试 → 用数据验证）
   ↓
🔥 grill-me（拷问追问 → 查漏补缺到死角）
```

| 场景 | 用哪个 |
|:----|:------|
| 脑子里的想法不确定靠不靠谱 | grill-me → 先拷问思维漏洞 |
| 方案已经基本确定，想验证 | pressure-test → 用真实数据验证 |
| 要对比两个方案 | pressure-test → 对拍模式 |
| 想全面分析一个东西 | prism → 先分析结构，再看要不要验证或拷问 |

**推荐流程：先 grill-me 想清楚，再 pressure-test 验证，prism 兜底做深度结构分析。**

---

## 经验教训

- **不要一个问题问到底。** 根据用户的回答动态调整下一个问题方向。
- **尖锐但要尊重。** 目的是帮用户，不是炫技。
- **宁可少问几个问题，也不要草草收场。** 覆盖所有关键维度比问满 20 个问题重要。
- 如果用户说"这个还没想清楚"，记下来作为未解决问题，别逼着给答案。
