# 级联检索方案压力测试报告

## 测试日期
2026-06-07

## 被测对象
级联检索链路：
① web_extract（requests 后端）→ ② web_search（searxng 后端）→ ③ 浏览器（Chromium，用完即关）

## 测试数据总览

| 测试项 | 调用次数 | 覆盖场景 |
|:------|:-------:|:--------|
| web_extract | 8 次 | 政府页/PDF/JS页/新闻/招标/批量 |
| web_search | 10 次 | 5个行业查询 + 4种同义词 + PDF回查 |
| 浏览器 | 2 次 | 常规页面/反爬页面 |
| 并发/性能 | 3 次 | 串行/并发/大内容 |

---

## 🔴 已确认的 5 个问题

### 问题 1：浏览器开销被严重低估（🔴 高优先级）
- **发现方式：** 实测浏览器启动后的 RSS
- **之前估算：** 300-500MB RSS
- **实际实测：** 1,162 MB RSS（14 个进程）
- **服务器总量：** 3.4 GB，占比 34%
- **影响：** 如果 SearXNG（143MB）+ Hermes（~336MB）已跑，开浏览器后可用内存骤降到 < 1GB，连续开两次可能导致 OOM
- **对策：** 开浏览器前必须检查可用内存（`free -m`），< 500MB 禁止启动

### 问题 2：级联缺少"成功即终止"守卫（🟡 中优先级）
- **发现方式：** 政府采购网页测试，web_extract 成功了（3100 chars）但逻辑没停
- **影响：** 成功后继续走浏览器浪费资源，浏览器返回 403 反而是倒退
- **对策：** `web_extract.error == null 且 content.length > 200` 时立即终止级联

### 问题 3：PDF 是完整盲区（🟡 中优先级）
- **发现方式：** 住建部 PDF 文件测试
- **原因：** requests 后端以 content-type 拦截 PDF：`Unsupported content type: application/pdf`
- **影响：** 建设行业大量标准文件是 PDF（GB/T、JGJ 等），这是关键缺口
- **对策：** 标记为"PDF 暂不支持全文提取"，替代方案：搜标题/摘要，或浏览器渲染后提取

### 问题 4：SearXNG 中文搜索噪声偏高（🟡 中优先级）
- **发现方式：** 5个行业查询实测
- **平均噪声率：** ~22%
- **最差场景：** 宜昌项目审批，40% 噪声
- **主要噪声源：** calculator.com（英文工具站）、餐厅百科（分词误匹配）
- **对策：** 同义词重搜可提升相关率 33%→60%，搜索不足时尝试 2-3 种关键词变体

### 问题 5：浏览器不是万能兜底（🟢 低优先级）
- **发现方式：** 政府采购网测试
- **现象：** web_extract 成功（200 OK），但浏览器返回 403
- **结论：** 某些网站反爬策略偏向封浏览器而非普通 HTTP，requests 反而能绕过简单反爬

## ⚠️ 预测风险

| 风险 | 概率 | 影响 | 
|:----|:---:|:----|
| 连续多次开浏览器→OOM | 🔴 高 | 服务崩溃 |
| web_extract 返回空但没报错→误判为成功 | 🟡 中 | 空结果分析 |
| SearXNG 搜不到生僻标准号 | 🟡 中 | 信息断层 |
| 代理故障导致 requests 全挂 | 🟢 低 | 全部回退到浏览器 |
| 浏览器被网站封 IP | 🟢 低 | 三级全挂，无信息 |
