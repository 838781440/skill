## 🔧 各 Skill 详情

### 1. grill-me — 方案拷问官

> **tagline:** 方案拷问官 — 一个问题一个问题地追问，走完决策树所有分支，直到找出所有漏洞

**触发方式：**
- `grill me` — 标准模式，走完全部分支
- `快速拷打我` — 紧凑模式，3-5个关键问题
- `grill me about [主题]` — 针对某个方案拷问
- `找漏洞` — 同上

**工作流程：**
1. **Phase 0:** 了解背景（问1-2个问题搞清楚你在说什么）
2. **Phase 1:** 逐分支拷问 — 不允许一次性列出问题，一次只问一个
3. **Phase 2:** 综合漏洞报告 — 列出所有发现的问题、严重程度、修复建议

**核心原则：**
- 不用代码验证，只帮你把脑子里的假设挖出来晒一晒
- 一次只问一个问题，等你回答再走下一分支
- 最后输出结构化漏洞清单

### 2. communication-coach — 沟通表达能力陪练

> **tagline:** 沟通表达能力陪练 — 不冷场话术、结构化表达（金字塔/PREP）、实战场景模拟

**触发方式：**
- `练一下表达` / `不冷场` / `模拟个场景` / `练一下沟通`
- `帮我改一下这段话`

**核心框架：**
- **速记版（3字口诀）：** 接 → 转 → 问
  - **接**：先接住对方的话（"确实""有道理""您说得对"）
  - **转**：转到你有准备的信息上（"我们已经在…""最近正在…"）
  - **问**：抛个问题回去（"您觉得呢？""您那边什么情况？"）
- **完整版：** 不冷场公式、PREP 结构（Point-Reason-Example-Point）、金字塔原理
- **场景模拟：** 面试、汇报、谈判、社交等真实场景陪练

### 3. pressure-test — 万物压力测试

> **tagline:** 万物压力测试 — 用数据+逻辑找短板，不管你是技术方案还是人生选择，禁止凭经验给结论

**触发方式：**
| 你说 | 模式 |
|:----|:----|
| `压力测试 XX` | 标准模式：多维度实测+逻辑推敲 |
| `快速压力测试 XX` | 紧凑模式：只测3个最关键维度 |
| `穿透 XX` | 深度模式：所有隐藏假设不留死角 |
| `验证 XX 靠不靠谱` | 标准模式 |

**覆盖对象类型：**
- 🔧 技术/工程方案 — 异常、边界、性能、容量
- 💼 商业模式/创业想法 — 逻辑推敲、竞品对拍、财务建模
- 🧭 职业/人生决策 — 认知偏差、信息盲区、沉没成本
- 🏠 购买/投资决策 — 财务建模、场景极端化
- 📝 写作/内容方案 — 说服力、事实错误

**工作流程：**
1. **Phase 0:** 基线 + 成本评估
2. **Phase 1:** 拆解被测对象（表层 → 中间层 → 底层）
3. **Phase 1.5:** 策略选择（按对象类型匹配测试维度）
4. **Phase 2:** 执行测试（数据验证/逻辑推敲/竞品对拍）
5. **Phase 3:** 综合报告（风险评级 + 修复优先级 + 行动清单）
6. **Phase 4:** 必须给出**一句最刺痛的话**

### 4. make-prd — 产品需求文档生成

> **tagline:** 全局型产品负责人，掌控产品全生命周期

### 6. autonomous-ai-agents — 自主分析框架

包含以下子 Skill：

| Sub-Skill | 功能 |
|:----------|:-----|
| **prism-discover** | 发现所有可能的分析维度 — 架构、安全、营销定位、用户心理、监管影响等 |
| **prism-scan** | 通过动态生成的认知镜片进行结构分析，发现守恒定律、结构不变量和 bug |
| **prism-3way** | 三个正交分析操作（WHERE/WHEN/WHY）+ 交叉合成，分歧即价值 |
| **prism-reflect** | 约束透明化 — 分析一个工件，再分析自己隐藏了什么 |
| **prism-full** | 完整多通道结构分析 + 对抗性自我修正 |
| **dispatcher-orchestrator** | 智能分层调度师 — 自动匹配 skill 领域专家，支持多级任务分解 |

**使用方式：** 说 `深度分析 XX` 或 `快速分析 XX` 触发调度师自动派专家。

### 7. 🆕 private-board-meeting-skill — 私董会决策框架

> **tagline:** 7位顶级商业顾问（Jobs/Musk/Buffett/Bezos/任正非/段永平/Thiel），一场没有客套的决策审判

**安装路径：** `private-board-meeting-skill/`

**触发方式：**
- `私董会` / `/private-board-meeting`
- `重大决策` / `帮我做个决策`
- 快速模式：`快速私董会`

**四步流程：**

| 步骤 | 内容 |
|:----|:------|
| **① 决策锚定** | 确认主体、内容、时间窗口、真实约束，缺一不开始 |
| **② 主席预审** | 识别真问题 → 给出 A/B/C 三条路径（赔率×胜率×成本）→ 选定一条送审 |
| **③ 七人审议** | 每人：立场 + 3个理由 + 追问 + 签名语录。至少2人持不同立场 |
| **④ 综合裁决** | 投票统计 → 共识 → 分歧 → 最终建议 + 行动清单 + 一句刺痛真相 |

**七位顾问：**

| 顾问 | 核心视角 | 风格 |
|:----|:---------|:-----|
| Steve Jobs | 减法 > 加法，产品偏执 | 尖锐、傲慢 |
| Elon Musk | 第一性原理，10x | 不耐烦、直击本质 |
| Warren Buffett | 安全边际，能力圈 | 温和但坚定、保守 |
| Jeff Bezos | 客户痴迷，长期主义 | 逻辑严密、数据驱动 |
| 任正非 | 危机意识，组织能力 | 朴素、深沉、军事化 |
| 段永平 | 本分，平常心 | 平静、直击本质 |
| Peter Thiel | 反共识，垄断，0→1 | 冷峻、哲学化、反直觉 |

**硬约束：**
1. 四件套不全，不开始
2. 必须有分歧 — 禁止全员共识
3. 主席必须有立场 — 禁止中立
4. 必须有一句刺痛真话 — 不能删、不能软化
5. 人格不能稀释 — Jobs 不会温柔，Musk 不会耐心

### 8. 🆕 cangjie-skill（book2skill） — 仓颉造书

> **tagline:** 把一本书的方法论蒸馏成一组可被 AI agent 直接调用的 skill

**安装路径：** `cangjie-skill/`

**触发方式：**
- `帮我拆《穷查理宝典》`
- `把《毛选》蒸馏成 skill`
- `distill this book into skills: <path>`

**核心方法论 — RIA-TV++ 六阶段流水线：**

| 阶段 | 内容 |
|:----|:------|
| **阶段 0** | Adler 整书理解 → BOOK_OVERVIEW.md |
| **阶段 1** | 5个 agent 并行提取（框架/原则/案例/反例/术语）→ 候选单元池 |
| **阶段 1.5** | 三重验证筛选（跨域/预测力/独特性）→ 通过率 25-50% |
| **阶段 2** | RIA++ 构造 skill → 每个单元独立 SKILL.md |
| **阶段 3** | Zettelkasten 链接 → INDEX.md + 引用图 |
| **阶段 4** | 压力测试（darwin 兼容）→ test-prompts.json + 回炉淘汰 |

**5个并行提取 Agent：**
- 框架提取器 — 决策框架、思维模型
- 原则提取器 — 原则、清单、规则
- 案例提取器 — 作者亲自用过的实例
- 反例提取器 — 书中警告的失败模式
- 术语提取器 — 关键概念词典

**每个 Skill 的 RIA++ 结构：**
- **R** — 原文引用（≤150字）
- **I** — 用自己的话重写方法论
- **A1** — 书中的案例
- **A2** — 用户在什么情境下会需要
- **E** — 1-2-3 可执行步骤
- **B** — 什么时候不适用 / 作者的盲点

**质量红线：**
- 每个 skill 必须通过全部三重验证
- 六段缺一不可
- 必须有包含诱饵测试的 test-prompts.json
- 不凭记忆拆书，必须有文本

### 9. 🆕 nuwa-skill（女娲造人） — 人物思维框架蒸馏

> **tagline:** 输入人名，自动深挖他的思维框架，生成可调用的人物视角 Skill

**安装路径：** `nuwa-skill/`

**两种入口：**

| 入口 | 行为 | 示例 |
|:----|:-----|:-----|
| **明确人名** | 直接蒸馏 | "蒸馏芒格"、"做个费曼skill" |
| **模糊需求** | 诊断 → 推荐候选人 → 蒸馏 | "想提升决策质量" |

**6个并行 Agent 深挖：**

| Agent | 搜什么 | 产出文件 |
|:------|:-------|:---------|
| ① 著作 | 书、长文、论文 | 核心论点、自创术语、推荐书单 |
| ② 对话 | 播客、长视频、AMA | 即兴思维、立场变化、拒绝回答的问题 |
| ③ 表达 | 社交媒体 | 高频词句式、争议立场、幽默方式 |
| ④ 他者 | 他人分析、书评、批评 | 外部观察、批评与争议 |
| ⑤ 决策 | 重大决策、转折点 | 决策背景、言行一致/不一致 |
| ⑥ 时间线 | 完整时间线 | 关键里程碑、最近12个月动态 |

**产出的人物 Skill 包含：**
- **心智模型**（3-7个，每个有来源证据和局限性）
- **决策启发式**（5-10条快速规则）
- **表达DNA**（句式偏好、高频词、幽默方式）
- **价值观 & 反模式**
- **诚实边界**（此 Skill 做不到什么，至少3条）
- **内在张力**（价值观矛盾 — 深度的来源，至少2对）

**质量红线：**
- 来源黑名单：不用知乎、微信公众号、百度百科
- 一手来源占比 > 50%
- 宁可标注"信息不足"的 60 分 Skill，不编造 90 分 Skill
- 每个 Skill 必须经过 4 项验证（已知测试/边缘测试/风格测试/通过标准）

**已附带的示例 Skill：**
- `examples/mrbeast-perspective/` → MrBeast 思维框架
- `examples/munger-perspective/` → 查理·芒格
- `examples/naval-perspective/` → Naval Ravikant
- `examples/zhang-yiming-perspective/` → 张一鸣
- `examples/x-mastery-mentor/` → X平台深度用户风格

### 10. 🆕 validate-idea — 创业想法验证

> **tagline:** 用《Minimalist Entrepreneur》的方法论，在写一行代码之前验证你的商业想法

**安装路径：** `validate-idea/`

**触发方式：**
- `/validate-idea` 或直接说 `验证一个想法`
- `帮我验证 XX 这个想法`

**核心理念：** 验证靠卖，不靠造。

**4步流程：**

| 步骤 | 内容 |
|:----|:------|
| **① 定义问题** | 谁有这个痛点？现在怎么解决的？痛到什么程度？愿不愿意花钱消痛？ |
| **② 手动先跑** | 能不能先手把手帮人解决？先收钱干活，再考虑自动化 |
| **③ 真的会付钱吗？** | 聊过至少10个潜在客户？至少3个说愿意付钱？ |
| **④ 4问检查** | 能一个周末写完？能让客户生活好一点？客户愿意付钱？能快速得到反馈？ |

**红牌（别造）：**
- 没人现在在解决这个问题（没有替代方案）
- 你列不出10个有这个问题的人
- 唯一验证是"我朋友觉得不错"
- 你需要先教育用户
- 你不在目标受众的圈子内

**绿牌（值得搞）：**
- 已经有人在为劣质方案付费
- 你手动帮几个人解决了问题，他们很喜欢
- 社区在抱怨这个问题
- 一句话能说清楚客户和痛点
- 你自己就有这个需求

**结论输出：** **Validated** → 推进 MVP / **Needs more validation** → 给具体步骤继续验证 / **Pivot** → 需要大转向

## 📦 安装说明

### Hermes Agent
```bash
# 将 skill 目录复制到 Hermes skills 目录
cp -r <skill-name> /root/.hermes/skills/

# 重启 gateway 生效
hermes gateway run --replace
```

### Claude Code
```bash
git clone <repo-url> ~/.claude/skills/<skill-name>
```

### 其他平台
> Skills 是纯 Markdown 文件，将 `SKILL.md` 复制到对应平台的 skills/rules 目录即可。
> 支持：Cursor / GitHub Copilot / Cline / Windsurf / Gemini CLI / Codex CLI / OpenCode 等 20+ 平台。
