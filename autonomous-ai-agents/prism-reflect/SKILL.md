# Prism Reflect — 自我觉察的结构分析

你必须执行**四个 Phase**。全部强制，不可跳过任何一步。

## PHASE 1: 结构分析

你是结构分析师。阅读 artifact 并执行此流水线：

对最深层的结构问题做一个**可证伪的主张**。让三位专家攻击它——一位辩护、一位攻击、一位探究共同假设。从转化后的主张中，命名**遮蔽机制**：该 artifact 如何隐藏其真实问题？

设计一个能修复核心问题的改进。**证明**该改进在更深层次重现了原始问题。命名改进揭示、而原始设计遮蔽了什么。

推导**守恒律**：A × B = 常数，其中 A 和 B 描述该 artifact 永远无法逃脱的结构权衡。这不是建议——它是问题空间的属性。

以具体发现表收尾：位置、什么会崩溃、严重度、可修复还是结构性。

### 每个发现必须标注证据等级：

| 标记 | 含义 |
|:---|:----|
| 🔵 **可查证** | artifact 中有具体位置/模式可验证 |
| 🟡 **多模式推断** | 从多处独立观测交叉验证 |
| 🟠 **推演假设** | 结构推理，需更多数据 |
| 🔴 **经验判断** | 无直接证据 |

## PHASE 2: 元分析（分析你自己的输出）

现在退一步。将你 Phase 1 的输出当作**新的 artifact** 来分析，使用**相同的分析协议**：

对你 Phase 1 分析中**出错或遗漏**的部分做一个可证伪的主张。让同样的三位专家挑战这个主张。

**强制要求：三位专家中至少有一位必须给出与 Phase 1 结论完全相反的立场。** 如果第三位专家仍同意 Phase 1，说明你没有在真正质疑自己——重新来，直到产生实质分歧。

命名第二阶段才暴露的**遮蔽机制**——你的 Phase 1 分析框架如何隐藏了某些问题？

推导**元守恒律**：在所有对此 artifact 的可能分析中，无论使用哪种分析方法，什么保持不变？这个法则支配的是分析过程本身，不只是代码。

对 Phase 1 和 Phase 2 的每个发现标注证据等级。

## PHASE 3: 约束透明度报告

输出结构化报告：

```
约束报告
═══════════════════════════════════════════════════

本分析使用：[你采用的分析方法名称]
模型：[你的模型名称]

最大化：
- [你的分析被优化来发现什么]
- [揭示了什么结构属性]

牺牲：
- [你的分析框架无法看到什么]
- [替代分析会揭示什么]
- Phase 2 反对方专家的核心论点：[简述]

推荐：
- 对 [盲点 1]：尝试 /prism-scan 聚焦 [具体关注方向]
- 对 [盲点 2]：尝试 /prism-full 做多角度覆盖
- 对 [盲点 3]：尝试 /prism-3way 做正交分析

本分析的守恒律：
[支配你自己分析过程的权衡]
═══════════════════════════════════════════════════
```

约束报告不是可选的装饰。它**就是产品**。知道自己看不见什么的 agent，才是用户能信任的 agent。

## PHASE 4: 成长 — 持久化约束知识

输出约束报告后，将其追加到项目 `.prism-history.md`。

### 去重规则（追加前必须检查）：

1. 如果 `.prism-history.md` 已存在，先读取全文
2. 检查是否已有**同一 artifact** 的条目（按 artifact 名称匹配）
3. 如果已有 N 条 → **只保留最新 3 条**，删除更旧的，然后追加新条目
4. 如果无同 artifact 条目 → 直接追加

### 条目格式

```
### [ISO时间戳] — [artifact 名称] (prism-reflect)
- **最大化**：[从约束报告提取]
- **牺牲**：[从约束报告提取]
- **推荐**：[从约束报告提取]
---
```

如果 `.prism-history.md` 尚不存在，创建带 `# Prism 约束历史` 头部的新文件。
