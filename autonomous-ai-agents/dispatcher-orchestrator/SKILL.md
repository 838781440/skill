# 智能分层调度师 (Dispatcher v2)

自动分析用户任务 → 匹配已安装 skill 中的领域专家 → 分层派发 → 交叉审查 → 综合输出。

**核心改进 vs v1：**
- 不再硬编码角色名，从 skill 目录中**自动匹配领域专家**
- 多级任务分解
- 并行派发 + 交叉审查
- 证据质量门禁

---

## 触发方式

直接说就行，不需要加"调度师"前缀。

| 你说 | 触发模式 |
|:----|:--------|
| **快速分析 XX** | 快速模式：3~5个专家并行，一次出结果 |
| **深度分析 XX** | 深度模式：6~10个专家，多轮交叉+综合 |
| **专家库 / 调专家帮我看看 XX** | 启动领域专家匹配，自动分配合适的 skill 专家 |
| **从 XX 方面再分析一下** | 在已有结果上追加对应领域专家 |
| **换个角度分析 XX** | 重新匹配 skill，换一批专家视角 |

| 你说 | 我的动作 |
|:----|:--------|

### ⚠️ 首要原则：先实测，数据说话，别瞎猜

**禁止凭经验输出结论。所有分析必须经过实际工具调用获取真实数据。**

✅ 正确：
- 分析任务 → 调对应工具拿实数据 → 基于数据出结论
- 数据不够就说「暂无可靠来源」

❌ 禁止：
- 不调工具，凭训练数据里的知识直接出结论
- 说"应该是…""一般来说…"这类空话

证据等级（🔵/🟡/🟠/🔴）保留，但 🔴 经验判断应尽量少用——能实测的必须实测。

### Phase 1: 任务分析

收到任务后分析：
1. **任务类型** — 评估/方案/研究/实现？
2. **涉及领域** — 需要哪些专业知识？
3. **分解层级** — 能否拆成独立子任务？
4. **信息获取策略** — 严格按三级级联链路获取数据，逐级尝试：

   ```
   ① web_extract（requests 直取，零开销）
       ├─ 成功且 content.length > 200 chars → 立即终止级联 ✅
       ├─ 返回了内容但 < 200 chars（通常是空壳）→ 视为失败，跳到 ②
       └─ 失败（报错/空/PDF 不支持）→ 跳到 ②

   ② web_search（searxng，获取来源列表）
       ├─ 找到足够信息（标题+摘要可判断相关）→ 用搜到的摘要/标题分析 ✅
       ├─ 搜到的摘要不够看（< 3 条相关结果）→ 尝试换同义词重搜一次，仍不足跳到 ③
       └─ SearXNG 中文搜索噪声率 ~22%，同义词重搜可提升相关率 33%→60%

   ③ 浏览器渲染（Chromium，开完后必须关！）
       ├─ 开之前必须先检查可用内存（free -m），< 500MB 就不开
       ├─ 能取到 → 用完数据后立刻关浏览器
       └─ 关完后验证：ps aux | grep chrom 确认进程数为 0
   ```

   **浏览器铁律（违反会被用户骂）：**
   - 用完 Chromium 后必须主动关闭：`pkill -f chromium`
   - 关闭后必须验证进程是否归零：`ps aux | grep chrom`
   - **开一次实测占 ~1,162 MB RSS（14 个进程），不是 300-500MB！** 3.4G 内存的服务器开一次吃掉 1/3 内存
   - **开浏览器前必须检查可用内存：** `free -m | awk '/^Mem:/{print $7}'`。低于 500MB 时禁止启动浏览器，直接报"内存不足，无法启动浏览器"，改为搜索或搜替代来源
   - 两次浏览器调用之间必须间隔至少 30 秒，留给系统回收内存
   - 浏览器只作为最后兜底手段，不能当常规提取工具用

   **完整流程示例：**
   ```python
   # 用户：快速分析 住建部关于检测资质的新政策
   
   # Step 1: 尝试 web_extract
   web_extract(["https://mohurd.gov.cn/xxx"])  
   # → 成功，拿到全文，直接分析 ✅（requests 后端，0.28s）
   
   # ⚠️ 已知盲区：requests 后端不支持 PDF（content-type 拦截）
   # 遇到 PDF 时 web_extract 直接报错，需标记为"PDF暂不支持全文提取"
   # 替代方案：搜索该 PDF 的标题/摘要，或建议用户手动查看
   
   # 如果 Step 1 失败（只给了 URL 但没具体页面，需要先找到链接）：
   # Step 2: 用 web_search 搜
   web_search("site:mohurd.gov.cn 质量检测 资质标准")  
   # → 拿到链接列表，再回到 Step 1
   
   # 如果搜索也找不到（反爬严的站）：
   # Step 3: 开浏览器直取
   browser_navigate("https://xxx.com")
   browser_snapshot(full=true)
   # 取完内容后：
   pkill -f chromium
   ps aux | grep chrom  # 确认 0 进程
   ```

### Phase 2: 领域专家派发

为每个领域派发一个子智能体。context 必须包含：
1. 该领域的 **skill 摘要**
2. **完整 task 描述**
3. **明确要求：必须加载对应的 skill 文件作为分析框架，不能只给一个角色名称空手进去**

**关键要求：子智能体必须加载 skill，不能空手进**

❌ 错误做法：派一个"经济专家"但不加载 skill，让他自己发挥。——没有框架支撑的分析就是个人观点。

✅ 正确做法：先 skill_view('finance-financial-analyst') 加载 skill 内容，带着 skill 的方法论框架进 context，要求 agent 按 skill 的格式输出。

示例（正确）：
```
context = f"""
你正在使用 **finance-financial-analyst** skill 作为方法论框架。
该 skill 的要求：
1. 先陈述假设，再给出结论
2. 必须构建场景分析
3. 区分事实与预测
4. 对每项建议做敏感性测试

你的任务：分析XXX
输出格式：【发现】【财务模型/推演】【关键假设】【敏感性分析】【证据等级】
"""
```

**输出格式必须匹配该 skill 的规范：**

| Skill | 输出格式要求 |
|:------|:----------|
| `finance-financial-analyst` | 【发现】【财务模型】【关键假设】【敏感性分析】【证据等级】 |
| `finance-fpa-analyst` | 【发现】【预算分析】【差异原因】【证据等级】 |
| `academic-psychologist` | 【发现】【心理机制】【框架依据】【文化语境】【证据等级】 |
| `academic-anthropologist` | 【发现】【文化功能】【社会结构关联】【民族志类比】【证据等级】 |
| `academic-historian` | 【发现】【历史脉络】【同期对比】【证据等级】 |
| `legal-contract-reviewer` | 【发现】【条款分析】【风险等级】【证据等级】 |
| `engineering-backend-architect` | 【发现】【架构分析】【方案对比】【证据等级】 |
| 其他通用 skill | 【发现】【分析推演】【证据等级】 |

**找不到直接对应的 skill 时怎么办：**
- 选最相近的类别（比如社会问题没有专门 skill 就用 academic-* 系列）
- 如果实在没有能用的 skill，用 prism-scan 作为通用分析框架
- 绝不能不加载 skill 直接派

> 实战胜例见 `references/agent-dispatch-with-skill-loading.md`

派发方式：
- **快速模式**：3~5 个专家并行，每人限 **5~10 次**工具调用。搜索和思考对半开，目标 **60 秒**出有深度的结论。
- **深度模式**：6~10 个专家，按依赖顺序派发，每人限 **10~15 次**工具调用。至少用一半调用做分析（对比、推演、找矛盾），不是纯搜索。

### ⚠️ 证据质量门禁（所有模式强制）

每条结论必须标记证据等级：

| 标记 | 含义 |
|:---|:----|
| 🔵 **可查证** | 有具体公开来源可查 |
| 🟡 **行业共识** | 多个来源交叉验证的普遍认知 |
| 🟠 **估算推演** | 基于公开数据推算得出 |
| 🔴 **经验判断** | 无直接数据，凭专业经验 |

格式：
```
📊 证据等级：🔵 / 🟡 / 🟠 / 🔴
```

末尾必须附证据清单汇总表。如果超过 50% 的结论是 🔴，需声明「本报告可靠性有限，主要基于经验判断」。

### Phase 2.5: 专家间交叉对质（深度模式强制）

专家输出原始结论后，调度师必须做**交叉对质**——不是简单的"汇总"：

1. **列出各专家结论中的冲突点**：比如经济专家说"房价收入比在下降"，社会专家说"年轻人说买不起房的比例在上升"——这不矛盾，但为什么？可能房价降了但收入预期也降了，实际购买力没改善
2. **找出盲点**：所有专家都忽略的维度是什么？
3. **验证共识**：如果多个专家从不同路径指向同一个结论，那这个结论可信度更高
4. **标记不确定性**：哪些结论数据支撑不足，需要更多验证

## 效率原则（诊断/查询类任务）

用户对**不必要的多步骤诊断**很敏感。当他说"你看下X是不是挂了"这类简单查询时：

### ❌ 之前犯过的错（别再来一遍）

检查 gbrain 是否挂了的正确做法 vs 错误做法：

| 做法 | 步骤数 | 用户反应 |
|:----|:------:|:--------|
| ✅ 直接调 MCP 工具测一下 | **1步** | ✅ 不说话（正常） |
| ❌ 查 systemd → 看日志 → 看 Nginx → curl 测端口 → 测外网 → 对配置 | **7步** | ❌ "你真的好花token" |

### ✅ 效率原则

1. **"是X挂了？"类查询 → 最直接的检测方法先上**
   - MCP 服务：直接调一个 MCP 工具（1步知死活）
   - 网络服务：直接 curl 测端口（1步知死活）
   - 进程存活：ps / systemctl status（1步知死活）
   - **只有直接方法失败了，才往下查原因**

2. **搜索/SearXNG 超时时的兜底链路**
   - SearXNG 超时 → 不要死磕重试搜索 → 直接去**权威来源官网**提取
   - 政府数据/政策：moe.gov.cn, gov.cn, mohurd.gov.cn 等直接 web_extract
   - 技术文档：直接去官方文档站提取
   - 这些站点的 requests 后端通常能正常工作，比搜引擎快

3. **省 token = 省用户耐心**
   - 能用 1 步解决的问题，不要走 3 步
   - 每一步工具调用都是 token，用户看得见
   - "先试最直接的方法"不是偷懒，是尊重

### 深度法则（2026-06-07核心升级）

**❌ 数据表 ≠ 深度分析。**
第一次做"年轻人躺平"深度分析时，每个专家只返回了数据点和结论的表格。用户说："内容有点干，数据点结论我自己上网查有什么区别？"

**✅ 每个专家必须有四个输出要素：**
1. **矛盾发现** — 数据之间的冲突，以及冲突暴露了什么
2. **因果链** — 至少3层因果推演，不能只给单层解释
3. **隐藏假设** — 该领域默认了什么前提，这个前提是否可靠
4. **与常识冲突** — 数据支持还是打脸大众认知

**✅ 调度师自己必须做交叉对质，不能只汇总：**
- 列出各专家结论的冲突点 → 分析为什么有分歧
- 找出所有专家都忽略的盲点
- 得出"只有把所有视角合并才能看到"的唯一洞察

详见 `references/deep-analysis-pattern.md` —— "年轻人躺平"分析的标准示范。

### 历史教训

- **微信输出不用 HTML 标签。** `<details>` `<summary>` 等标签微信不解析，用 `---` 和 `>` 替代。
- **专家不能空手进去。** 每次派 agent 必须先 skill_view() 加载对应 skill，把 skill 的方法论框架写进 context。没有框架的分析就是个人观点。——这条是 2026-06-07 用户三连纠正学会的。
- **prism 不是调度师的替代品。** prism 是派发给 agent 的深度分析工具之一，不是用户说"深度分析"时的直接入口。入口永远是调度师。
- **快速模式也不能省略 skill 加载。** 用户说"快速分析结婚成本"一样要先 load 财务分析师 skill 再派。省这一步的代价是用户说"内容有点干"。
- 浏览器开销不能靠估算（实测1,162 MB/14进程）。
- 成功的定义要量化，不要"感觉还行"。
